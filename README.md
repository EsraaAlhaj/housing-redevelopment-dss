# نظام دعم القرار لإعادة تأهيل الإسكان (Housing Redevelopment DSS)

نظام دعم قرار متعدد المعايير (MCDA/WSM) لتحديد أولويات مشاريع إعادة تأهيل الإسكان،
يعمل بالكامل محليًا دون أي اتصال بالإنترنت أو واجهات برمجية مدفوعة.

## الخصائص الأساسية

- **بدون تكلفة**: لا مفاتيح API، لا خدمات سحابية مدفوعة، لا اعتماد على الذكاء الاصطناعي عبر الإنترنت.
  كل الحسابات تتم محليًا بلغة Python.
- **محرك تقييم شفاف**: 7 مؤشرات رسمية (الحالة الإنشائية 35%، الأهمية الاستراتيجية 15%،
  عمر المبنى 15%، الكثافة السكانية 10%، التعديات غير المرخصة 10%، البيئة العمرانية 5%،
  البنية التحتية 10%) بأسلوب Weighted Sum Model مع إعادة توزيع الوزن على المؤشرات
  المتاحة فعليًا (لا يتم تعويض البيانات الناقصة بصفر أبدًا).
- **لوحتا معلومات رئيسيتان فقط**:
  1. **① تقييم حالة الإسكان** — صورة الحالة الراهنة (الحالة العامة، العمر، الكثافة،
     التوزيع الجغرافي حسب الحي، مستكشف بيانات المشروعات).
  2. **② دعم قرار إعادة التأهيل** — خريطة حرارية لـ 29×7 (مشروعات × مؤشرات)، ترتيب
     الأولوية، مقارنة المشروعات، تحليل "ماذا-لو" للأوزان (مع تحليل حساسية Monte
     Carlo)، وملخص قرار نهائي يتطلب توصية وسببًا بشريًا موثَّقًا — **النظام لا يُصدر
     أبدًا توصية إزالة/ترميم تلقائية**.
  وظائف إدارة البيانات/الدراسات/المؤشرات/التصدير لم تُحذف؛ أصبحت متاحة من نوافذ
  حوارية (`st.dialog`) يتم استدعاؤها من الشريط الجانبي «⚙️ الإدارة والبيانات».
- **قابل لإعادة الاستخدام**: لا يوجد أي افتراض مُبرمج مسبقًا بعدد السجلات أو أسمائها.
  يمكن رفع أي ملف Excel/CSV بأي بنية أعمدة وربطها بالحقول القياسية.
- **دراسات متعددة ومستقلة**: كل "دراسة" تحتفظ ببياناتها ومؤشراتها وسيناريوهاتها
  بشكل مستقل تمامًا عن الدراسات الأخرى. مجموعتا بيانات بورسعيد (29 مشروعًا النشطة
  حاليًا، و30 مشروعًا التاريخية) محفوظتان كدراستين منفصلتين تمامًا ولا تُدمجان أبدًا.
- **تخزين دائم**: قاعدة بيانات SQLite محلية (`data/housing_dss.sqlite3`) تحافظ على
  جميع البيانات بين جلسات التشغيل.

## التثبيت والتشغيل (ويندوز)

### المتطلبات
- Python 3.10 أو أحدث مثبّت ومتاح في PATH.

### التشغيل السريع
1. افتح المجلد `housing_dss`.
2. شغّل الملف `run_app.bat` بالضغط المزدوج عليه (ينشئ بيئة Python الافتراضية،
   يثبّت المتطلبات تلقائيًا في أول تشغيل، ثم يفتح التطبيق في المتصفح).

### التشغيل اليدوي (بديل)
```
cd housing_dss
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```
سيفتح التطبيق تلقائيًا على `http://localhost:8501`.

في أول تشغيل، يقوم النظام تلقائيًا بتحميل دراسة **"بورسعيد - 29 مشروعًا (الدراسة
النشطة)"** من `data/sample/PortSaid_29_Selected_Projects.xlsx` وتفعيلها، بالإضافة
إلى تحميل دراسة **"بورسعيد - 30 مشروع (دراسة الحالة الأولى)"** من الملف الأصلي
كدراسة تاريخية مستقلة غير نشطة (لا تُحذف ولا تُدمج مع الدراسة الجديدة). يمكن التبديل
بين الدراستين من قائمة "الدراسة النشطة" في الشريط الجانبي في أي وقت.

## تشغيل الاختبارات
```
cd housing_dss
python -m pytest tests/ -v
```
تم تنفيذ 29 اختبارًا (وحدات + تكامل + فحص شامل لكلا لوحتي المعلومات عبر AppTest)
وجميعها ناجحة، وتغطي: السيناريوهات العشرة الأساسية (الاستيراد، رفع مجموعة بيانات
مختلفة، إضافة/تعديل مشروع، بقاء البيانات بعد إعادة التشغيل، تغيير الأوزان وإعادة
الحساب، فصل الدراسات، عدم تلفيق القيم الناقصة، التصدير)، بالإضافة إلى: تحليل
الحساسية، تسجيل/تحديث توصيات القرار (`DecisionNote`)، وتحميل الدراستين (29 + 30)
بشكل منفصل دون دمج عند أول تشغيل.

## منهجية التقييم وقواعد الشفافية

- **لا تلفيق للبيانات الناقصة**: أي مؤشر بلا قيمة مصدر يُصنَّف "بيانات غير كافية"
  (`insufficient`) ولا يُحتسب كصفر، بل يُستثنى من المجموع المرجّح ويُعاد توزيع
  الوزن على المؤشرات المتاحة فقط. في الخريطة الحرارية تظهر هذه الخلايا باللون
  الرمادي صريحًا (وليس صفرًا ملوَّنًا).
- **التصنيف**: كل مشروع يُصنَّف "موثّق" (Validated) أو "مبدئي" (Provisional) أو
  "بيانات غير كافية" (Insufficient Data) حسب نسبة اكتمال المؤشرات ووزن المؤشر
  المهيمن، وفق عتبات قابلة للتعديل من إعدادات الدراسة.
- **التعديات غير المرخصة والبنية التحتية**: تُحتسب دائمًا كـ"مبدئي" (provisional)
  لأن وجود امتداد لا يعني بالضرورة أنه غير مرخّص، والاتصال بالخدمة لا يعني جودتها.
- **تنبيهات السلامة الإنشائية** (إزالة/ترميم) تُحسب بشكل مستقل تمامًا عن الترتيب
  التركيبي، وتظهر كشارة منفصلة في كل الصفحات.
- **لا خريطة جغرافية مُلفَّقة**: عمود "SHAPE *" في الملف الأصلي يحتوي فقط على
  تصنيف هندسي عام ("Polygon") دون أي إحداثيات فعلية؛ لذلك لا تُعرض خريطة بإحداثيات
  مُفترضة. يُستخدم بدلاً منها توزيع تحليلي حسب الحي، مع توضيح صريح لهذا القيد في
  لوحة ①.
- **القرار النهائي بشري دائمًا**: درجة الأولوية المركّبة في لوحة ② هي أداة دعم
  قرار فقط. ملخص القرار يتطلب من المستخدم اختيار توصية من قائمة محدودة وكتابة
  سبب نصّي قبل الحفظ؛ النظام لا يختار توصية تلقائيًا ولا يفترض إزالة أو ترميم.
- **المؤشرات الجديدة غير المدعومة**: إذا طلب المستخدم طريقة حساب غير مدعومة علميًا
  لمؤشر جديد، يُعلَم النظام بذلك بوضوح كـ"قيد" (limitation) ولا يخترع معادلة.

## النشر الاختياري على Streamlit Cloud (غير إلزامي)

يمكن تشغيل هذا الكود على `streamlit.io/cloud` المجاني إذا رغب المستخدم، لكن يجب
التنبيه إلى القيود التالية بوضوح قبل الاعتماد عليه لأي بيانات حقيقية:
- التخزين على الطبقة المجانية **غير دائم** (ephemeral) — أي إعادة بناء للتطبيق
  (redeploy) أو إعادة تشغيل الحاوية قد تمحو ملف SQLite بالكامل.
- لا يوجد ضمان على ديمومة البيانات بين الجلسات في الاستضافة السحابية المجانية.
- للاستخدام الإنتاجي الحقيقي، يُنصح بالتشغيل المحلي أو خادم خاص مع تخزين دائم
  (volume) خارج دورة حياة الحاوية.
